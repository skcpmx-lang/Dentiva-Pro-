1. About Dentiva Pro

Dentiva Pro is a desktop application for a dental practice. Every patient record, appointment, prescription, invoice, payment, stock movement and audit entry is stored in a single database file on this computer. The application never needs the internet: it works the same on a clinic network with no connection at all.

RequirementDetail
Operating systemWindows 10 or Windows 11 (64-bit)
Display1366 × 768 or larger; scales cleanly up to 4K at 100–200 % scaling
DiskAbout 400 MB for the program plus the space your records need
PrinterAny Windows printer — A4/A5 laser, thermal receipt, Bluetooth or wireless
InternetNot required for daily use. Only the optional update check needs it
Where your data lives. By default: %APPDATA%\Dentiva Pro — containing Data\dentiva.db (the database), Attachments\ (scanned files and images), Backups\, Logs\ and Config\. Uninstalling the program never deletes this folder.

2. Installing and first run

  1. Run DentivaPro-Setup-1.0.0-x64.exe and choose the installation folder if you do not want the default. The installer is per-user by default, so it does not need an administrator password, but it can be elevated if you prefer a machine-wide install.
  2. Start Dentiva Pro from the Start menu or the desktop shortcut.
  3. The setup wizard opens the first time only.

Step 1 — Activation

Enter the one-time activation code supplied with your licence and choose Activate. The code is verified on this computer without contacting any server. Ten wrong attempts start a 60-second cool-down; every attempt is written to the audit log.

Step 2 — Clinic details

Enter the clinic name (English and, optionally, Bengali), address, phone numbers, e-mail, website and registration number. Choose the clinic logo (PNG/JPEG, up to 2 MB) if you have one. The clinic block appears at the top of every printed prescription and invoice — nothing else is printed in the header.

Step 3 — Dentists

Add each dentist who signs reports: full name, one or more designations, one or more qualifications, registration number, phone, e-mail, signature image and consulting hours. You can add more later in Administration → Dentists.

Step 4 — Administrator

Create the first administrator account. Choose a username and a password of at least 10 characters. Passwords are stored with scrypt hashing; nobody — including the Dentiva Pro team — can read them back. Keep this password safe: it is the account that can restore backups and change permissions.

Activation is honest about what it is. The application ships with a fixed offline secret, so a determined person with the source code and the binary can recover it. Activation protects against casual copying and clearly records which clinic installed the product; it is not, and cannot be, cryptographically unbreakable without an online licence server.

3. The main window

  • Header: clinic logo and name, the notification centre bell (low stock, expiring batches, backup results, appointment reminders), the lock button, and the user menu (profile, change password, About, sign out).
  • Sidebar: collapsible groups — Practice (dashboard, appointments, queue, patients), Clinical (visits, dental chart, prescriptions, treatments), Billing (invoices, payments, inventory, accounting, reports) and Administration (staff, audit log, backups, settings, About). Your role decides which entries appear, and the service layer refuses anything your role is not allowed to do even if the screen were reached another way.
  • Global search (Ctrl+K) finds a patient by code, name (English or Bengali) or phone, from anywhere in the application.
  • Keyboard: Ctrl+K search · Ctrl+L lock · Ctrl+P print the current document · Esc close a dialog · Enter confirm · Ctrl+S save a form.

4. Patients

Practice → Patients lists patients newest first. Filter by date range (today, this week, this month, custom) and search by name, code or phone. The list is paged, so it stays fast with many thousands of records.

  • Every patient gets a unique, sequential patient code; the code is used on prescriptions, invoices and attachments.
  • Open a patient to see the profile: overview, dental chart, timeline, visits, appointments, treatments, prescriptions, invoices, payments, referrals and attachments — each on its own tab.
  • Archive a patient who has left the practice. Archived patients are hidden from the register but keep every record; an administrator can restore one at any time with the same code.
  • Clinical and financial history is never deleted. Corrections are added as new entries so the original stays visible (see §5).

5. Visits and the dental chart

A visit records what happened on a date: complaints, examination, diagnosis, treatment performed, advice and follow-up. A visit starts as draft and is finalised when the clinician signs it off. A finalised visit can no longer be edited directly — amending it creates a clearly marked correction, and both versions stay in the history.

The dental chart uses FDI notation (11–48 permanent, 51–85 primary). Click a tooth to record its condition and treatment; each entry is stored with the visit it belongs to, so you can see how the chart looked at any point in time.

6. Appointments and the queue

  • Create an appointment with patient, dentist, date, start time, duration and reason. Statuses: scheduled, confirmed, arrived, in treatment, completed, cancelled, no-show and rescheduled.
  • Queue shows the patients waiting today, ordered by priority (emergency, urgent, normal) and then by position. You can move an entry within its priority, mark it in treatment or completed, and the queue is stored in the database, so it survives a restart.
  • The dashboard shows today's appointments and the live queue count.

7. Treatment catalogue

Clinical → Treatments holds the procedures your clinic performs with their default fee, category and description. Treatments are used when writing prescriptions and when building invoices; deactivate a treatment instead of deleting it so old invoices keep their details.

8. Prescriptions

A prescription has four narrative blocks and a structured medicine table:

BlockWhat goes in it
C/C — Chief complaintsOne line per complaint, chosen from your clinic list or typed
O/E — On examinationFindings, e.g. “Deep caries in 36”
R/E — Rx / RecordsInvestigations, diagnosis and medicines
AdviceInstructions such as “Warm saline rinse twice daily”

Each medicine row carries the medicine name, type (tablet, syrup, mouthwash…), strength, dose, the morning/noon/night slots, before or after food, duration with its unit, quantity, and an optional conditional instruction such as “if pain occurs”. Rows can be reordered and removed. Rows can be saved as a draft while you are still working, or finalised and printed.

Signature area. The printed prescription reserves a blank area of at least 25 mm below the dentist's block for a wet signature. No text is printed in that space, and that is deliberate — the clinic signs the paper.

9. Printing and PDF

  • Every printable document first opens a preview that shows exactly what will be printed, including Bengali text.
  • Paper sizes: A4, A5, thermal 80 mm and thermal 58 mm. Choose the paper per document; the layout adapts.
  • Printer profiles (Settings → Printing) remember which printer, tray, paper and number of copies each document type uses — including Bluetooth and wireless printers installed in Windows.
  • Save as PDF writes a PDF with the fonts embedded, so Bengali text renders exactly as on screen. Choose where to save it when asked.
  • Invoices print with the clinic name, logo, address and phone only. There is no signature block on the invoice, and no other footer.

10. Invoices and payments

  • An invoice is built from treatments, products or free-text lines, with quantity, unit price and line discount, then an invoice-level discount, tax and an optional round-off to whole taka.
  • All money is handled in poisha internally, so totals never drift by a paisa. BDT (৳) is the only currency.
  • Payments can be cash, bank transfer, card, bKash, Nagad, Rocket, Upay or other. Mobile-wallet payments require the transaction reference.
  • A payment can be applied to one invoice or held as an advance; the patient's balance shows the net position, and an advance appears as a credit.
  • Invoices and payments are never deleted: void them with a reason and the record stays, marked as void, with the reason and the user who voided it.
  • Payments → Dashboard opens on today by default, with the day's collection split by method. The accounting figures always separate invoiced revenue from cash received.

11. Inventory

  • Items hold name, category, unit, reorder level, default supplier and sale price.
  • Stock is received in batches with batch number, expiry date, quantity and unit cost. Issuing stock consumes batches in expiry order and refuses to issue more than is on hand.
  • Low-stock and expiring-soon warnings appear on the dashboard and in the notification centre.
  • Every movement (purchase, usage, wastage, return, expired, adjustment) is stored permanently with the user and the reason.

12. Accounting and reports

  • Expenses are recorded with category, date, amount, payment method and payee.
  • Accounting shows invoiced revenue, cash collected, expenses, outstanding patient balances and net cash flow for the chosen period, plus a per-method breakdown.
  • Reports cover daily/monthly revenue, treatment revenue, expenses, outstanding invoices, stock levels and the audit trail. Every figure is calculated from the transactions in the database — nothing is estimated or hard-coded.
  • Reports and lists export to CSV (Excel) and print on A4 or A5.

13. Staff and permissions

Administration → Staff holds every user account: receptionists, assistants, dentists and administrators. Each account has a role, and a role is a list of permissions such as patients.create, invoices.void or backup.restore. You can also grant or deny individual permissions to a single account.

  • Permissions are enforced in the service layer, not by hiding buttons: a screen that is reached in any way still cannot do what the role forbids.
  • A denial always wins over a grant. The last administrator account cannot be deleted or demoted, so a clinic can never lock itself out.
  • Removing a staff member deactivates the account and keeps every record they created.

14. Security and the audit log

  • Passwords: minimum 10 characters, stored with scrypt (N = 2¹⁵, r = 8, p = 1). Five wrong sign-in attempts lock the account for five minutes.
  • Auto-lock: the session locks after 5, 10, 15 or 30 minutes of inactivity (configurable) or immediately with the lock button or Ctrl+L. Signing back in needs the password.
  • Audit log: who did what, when, to which record — including refused actions, restores, backups, permission changes and destructive confirms. Entries are hash-chained and the database refuses to update or delete them; if the chain is broken by an external tool, the integrity check reports it.
  • Destructive actions require a typed confirmation phrase (for example DELETE ALL STRESS DATA) and the administrator password, and take a safety backup first.

15. Backups and restoring

Automatic

Choose an interval (7, 15 or 30 days) and a time of day. The application takes a backup on the first start after that time and keeps the number of copies you configure. Backups are written as DentivaPro_Backup_YYYY-MM-DD-hh-mm-ss folders containing the database, the clinic configuration, attachments, a manifest with checksums, and a plain-text README.

Manual

Administration → Backups → Create backup. Choose whether attachments are included, then optionally Copy to… to place the folder on a USB drive or a network share. Take a manual backup before and after any major change.

Verifying

Verify re-checks every checksum, opens the database, runs SQLite's integrity check and verifies the audit chain. A backup that fails verification is reported with the exact problem. The same check is available outside the application: node scripts/verify-backup.mjs "<backup folder>".

Restoring

  1. Open Administration → Backups and choose Restore next to the backup.
  2. Type the confirmation phrase RESTORE BACKUP and enter your password.
  3. The application verifies the chosen backup, takes a pre-restore backup of the current data, stages the new database, switches over, re-verifies and only then reports success.
  4. If anything fails it rolls back to the data you had, keeps the pre-restore backup and records the failure in the audit log. Nothing is ever silently lost.
  5. After a restore everybody must sign in again, because the user list came from the restored file.

16. Settings and data management

  • Clinic — name, address, phones, e-mail, logo, footer quote for printouts.
  • Clinical lists — the options offered for chief complaints, examination findings, medicine types and timings, advice and duration units. Your clinic can rename, add or deactivate entries without touching the built-in lists.
  • Printing — paper size per document, printer profiles, copies.
  • Security — auto-lock interval, password policy reminders, session behaviour.
  • Backups — automatic schedule, retention, backup folder.
  • Data — open the data folder, run a full integrity check, export data (CSV), and see the database size.
  • Diagnostics — recent log entries and “Export logs” to send a bundle to support. Logs are rotated automatically and never contain passwords.

17. Troubleshooting

SymptomWhat to do
The application will not start Restart the computer, then start Dentiva Pro again. If it still fails, open %APPDATA%\Dentiva Pro\Logs, find the newest file and use Diagnostics → Export logs from another account or send the file to support.
A page looks empty The filter above the list may exclude everything (for example a custom date range in the future). Clear the filter and reload the page.
Bengali text prints as boxes The bundled Noto Sans Bengali font is used automatically. Make sure you print through Dentiva Pro's preview rather than copying text into another program.
Nothing prints / the wrong printer is used Check Settings → Printing: the document type must have a printer profile, and the printer must be online and installed in Windows.
“Your role does not allow this action” Ask an administrator to grant the permission in Administration → Staff, or sign in with an account that has it.
A restore was refused The backup failed verification, or the confirmation phrase or password was wrong. The refusal is recorded in the audit log along with the reason.
Automatic backup did not run today Automatic backups run at the configured time on the first start after it, and only when the interval has elapsed. Use Create backup for an immediate copy.

18. Licence, version and third-party notices

Administration → About shows the product name, version, build number, commit, build date, database path, log path, backup folder, the licence (“Proprietary — single-clinic licence”), and the full list of third-party components with their licences (also shipped as THIRD-PARTY-NOTICES.txt next to the program).
